# 主代理验收报告样例

子代理说完成，不等于真的完成。

主代理必须回收证据，再判断是否允许进入下一步。

## 示例场景

用户任务：给 demo 项目补一个首页状态卡片说明。

子代理分工：

- 产品角色：整理需求和验收标准。
- 开发角色：修改页面文案。
- 测试角色：检查页面是否符合标准。

## 验收报告模板

```text
任务目标：
本轮要完成什么。

子代理输出摘要：
每个子代理做了什么，输出了什么。

证据：
1. 修改了哪些文件。
2. 检查了哪些页面或文档。
3. 对照了哪些验收标准。
4. 是否有截图、命令结果或文件片段。

发现的问题：
1. 哪些地方没有完成。
2. 哪些地方只有口头说明，没有证据。
3. 哪些地方超出了任务范围。

主代理结论：
PASS / PARTIAL PASS / FAIL

是否允许进入下一步：
允许 / 不允许

下一步建议：
只写建议，不擅自执行高风险动作。
```

## 填写样例

任务目标：

补清楚 demo 项目首页状态卡片的字段说明。

子代理输出摘要：

产品角色整理了 4 个字段：名称、状态、来源、最近更新时间。

开发角色修改了首页说明文档。

测试角色对照验收标准做了只读检查。

证据：

1. 首页说明文档已出现 4 个字段。
2. 每个字段都有含义解释。
3. 文档明确写了“来源缺失时显示待接入”。

发现的问题：

1. 还没有真实页面截图。
2. 还没有接入真实数据。
3. 当前只适合进入文档预览，不适合宣布上线。

主代理结论：

PARTIAL PASS

是否允许进入下一步：

允许进入文档预览。

不允许进入发布。

下一步建议：

补一张字段来源表，再决定是否开发页面。

## 验收红线

以下情况不能判 PASS：

1. 只有“我完成了”，没有证据。
2. 只改了文案，没有对照目标。
3. 子代理擅自扩大范围。
4. 没检查不做事项。
5. 下一步涉及发布、公开、交付，但没有人工确认。
