# Start Here Task：只读检查 demo-workspace

请你对下面的输入目录做一次只读检查。

## 目标

判断这个 AI Agent 工作台 demo 是否具备清楚的事实源、团队边界、角色档案、角色记忆和下一步建议。

## 输入目录

```text
demo-workspace/
```

## 禁止事项

- 只读，不要修改任何文件。
- 不要创建新文件。
- 不要删除、移动、重命名文件。
- 不要联网。
- 不要上传任何内容。
- 不要读取输入目录以外的敏感信息。
- 不要处理密钥、账号、真实聊天记录或真实客户信息。
- 不要给没有文件依据的结论。

## 检查重点

1. 事实源是否清楚：项目 registry、STATE、progress 是否能说明当前状态。
2. 团队边界是否清楚：product-team、engineering-team、qa-team 的职责和读写边界是否明确。
3. 角色档案是否清楚：product-manager、engineer、qa-reviewer 是否知道自己该做什么和不能做什么。
4. 角色记忆是否存在：每个角色是否至少有 experience-log 和 failure-log。
5. 下一步建议是否能从文件中推导出来。

请按下面格式输出：

```text
一、总体结论：PASS / PARTIAL PASS / FAIL

二、事实源检查
- 结论：
- 文件证据：

三、团队边界检查
- 结论：
- 文件证据：

四、角色档案检查
- 结论：
- 文件证据：

五、角色记忆检查
- 结论：
- 文件证据：

六、主要缺口
- 缺口 1：文件证据 + 说明
- 缺口 2：文件证据 + 说明

七、下一步建议
- 建议 1：对应文件
- 建议 2：对应文件

八、是否适合复制成自己的项目工作台
- 结论：
- 理由：
```

## 验收标准

- 每个结论必须指向具体文件。
- 如果文件不存在，要明确写出缺失路径。
- 如果信息不足，要写“信息不足”，不要猜。
- 不要输出任何敏感信息。
- 不要执行任何写入操作。
