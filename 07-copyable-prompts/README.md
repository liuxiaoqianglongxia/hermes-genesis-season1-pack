# 任务提示词使用说明

这个目录里的提示词，是给你复制后改成自己任务用的。

不要原样丢给 AI 就期待它自动懂你的项目。

每次复制前，至少要替换目标、输入材料、禁止事项、输出格式和验收标准。

---

## 使用前先替换这些变量

常见占位内容：

- `<文章标题>`：换成你的文章名。
- `<项目名称>`：换成你的项目名。
- `<仓库名>`：换成你的仓库或目录名。
- `<待发布材料目录>`：换成你要检查的资料目录。
- `<文件 1>`、`<文件 2>`：换成真实输入文件。
- `<目标读者>`：换成读者类型。

如果输入材料不明确，AI 很容易自由发挥。

---

## 每个任务提示词必须包含五件事

### 1. 目标

写清楚本轮只解决什么。

坏例子：

```markdown
帮我优化一下。
```

好例子：

```markdown
目标：只读检查资料包是否存在过度承诺，不修改文件。
```

### 2. 输入

告诉 AI 应该看哪些材料。

```markdown
输入：
- packages/example/README.md
- packages/example/10-FAQ/不承诺事项.md
```

### 3. 禁止事项

禁止事项比目标更重要。

```markdown
禁止：
- 不要修改文件
- 不要扩大到无关目录
- 不要调用外部平台
- 不要处理敏感凭据
```

### 4. 输出格式

固定输出格式，减少废话。

```markdown
输出：
一、总体结论
二、阻塞问题
三、非阻塞问题
四、建议下一步
```

### 5. 验收标准

让 AI 知道什么叫合格。

```markdown
验收：每条问题必须指向具体文件或章节；没有证据的判断必须标为假设。
```

---

## 不要让 AI 自由发挥到无边界

如果你只写“帮我看看”，AI 可能会：

- 顺手改写全文。
- 扩大到整个仓库。
- 把建议说成事实。
- 忘记安全边界。
- 开始做你没授权的发布准备。

更好的写法：

```markdown
你是只读检查子代理。
本轮只检查 <目录>。
不要修改文件。
不要调用任何外部平台。
输出问题清单和建议，不要直接执行。
```

---

## 不要把敏感信息贴给 AI

不要贴：

- 密钥
- 私人身份信息
- 真实客户数据
- 内部群信息
- 真实运行载荷
- 未脱敏合同或订单
- 账号凭据

如果确实需要 AI 帮你检查结构，请先脱敏。

脱敏方法：

- 人名改成“用户 A”。
- 项目名改成“demo-project”。
- 路径改成相对路径。
- 数字保留量级，不保留真实编号。
- 删除所有凭据字段。

---

## 推荐使用顺序

1. 先用 `subagent-dispatch-task.md` 学会派单边界。
2. 再用 `team-boss-planning-task.md` 拆一轮任务。
3. 写文章时用 `article-review-task.md` 做发布前审稿。
4. 涉及仓库时用 `github-qa-task.md` 做只读检查。
5. 涉及资料包或发布材料时用 `publish-check-task.md` 做安全检查。
6. 涉及 Dashboard 时用 `dashboard-audit-task.md` 检查是否只是空壳。

每个提示词都是起点，不是万能答案。

真正重要的是：目标清楚、输入清楚、禁止事项清楚、验收清楚。
