# Dashboard 数据源结构说明

Dashboard 不是装饰页面。

它的价值不是把页面做得很酷，而是让系统真实状态变得可见。

## 基本原则

1. Dashboard 不应该凭空造数据。
2. 每个字段都要能说明来自哪里。
3. 第一版可以很简单，甚至可以先用 Markdown 表格模拟。
4. 等字段稳定后，再考虑做前端页面和后端接口。

## 六个页面应该读什么

| 页面 | 应该展示什么 | 建议事实源 |
| -- | -- | -- |
| 端口状态 | 服务名、端口、是否可访问、最近检查时间、异常摘要 | 项目 STATE、端口规范、只读探测结果 |
| Agent / 角色 | 角色名、职责、所属团队、最近任务、记忆状态 | 角色档案、角色记忆目录、团队注册表示例 |
| 定时任务 | 任务名、计划时间、最近结果、失败原因、下一次运行 | 定时任务清单、任务结果记录、人工确认记录 |
| 技能 | 技能名、适用场景、所属分类、最近维护时间、风险说明 | 技能目录、技能说明文件、维护记录 |
| 流水线 | 任务从提出到验收经历了哪些阶段、卡在哪一步 | 任务记录、验收报告、项目 progress |
| 模型调用与用量 | 调用来源、任务类型、粗略用量、异常调用 | 运行记录、任务摘要、人工复盘记录 |

## 第一版怎么做

不要一上来写完整后端。

可以先建一个 `dashboard-source-table.md`：

```text
| 模块 | 字段 | 来源文件 | 最近更新 | 是否可信 | 备注 |
| -- | -- | -- | -- | -- | -- |
| 端口状态 | 前端端口 | STATE | 2026-xx-xx | 是 | 手工确认 |
| 角色 | 产品经理职责 | role profile | 2026-xx-xx | 是 | demo 角色 |
| 定时任务 | 每日检查 | task record | 2026-xx-xx | 待确认 | 先人工记录 |
```

这张表跑通后，再决定哪些字段值得做成页面。

## 不建议第一版做什么

- 不建议一上来做完整后端。
- 不建议一上来做复杂权限。
- 不建议一上来做自动启停服务。
- 不建议一上来做实时大屏。
- 不建议把展示层当事实源。

## 正确理解

Dashboard 是镜子，不是大脑。

事实源仍然应该放在项目状态、团队边界、角色档案、任务记录和验收报告里。

Dashboard 只负责把这些事实展示出来。
